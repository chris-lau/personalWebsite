# Phase 4 Implementation Plan — PostgreSQL and CRUD

## Executive Summary

Phase 4 introduces persistent database storage to the Personal OS backend service. It replaces static local JSON loading with SQLAlchemy models and Alembic migrations, utilizing SQLite for local development and Aiven PostgreSQL for production deployment, complete with graceful fallback mechanisms.

---

## Key Requirements & Scope

1. **Dual Database Architecture:**
   - **Local:** SQLite (`sqlite:///./personal_os.db`).
   - **Production:** Aiven PostgreSQL (`DATABASE_URL` environment variable).
2. **Database ORM & Migrations:**
   - SQLAlchemy 2.0 ORM models (`Project`, `Technology`, `NowEntry`, `ReadingItem`).
   - Alembic for database schema versioning and autogenerated migrations.
3. **Seeding Pipeline:**
   - `seed.py` script to populate database tables from existing `projects.json` and `now.json` files.
4. **API Integration & Resilience:**
   - Update `/api/projects` and `/api/now` to query from database.
   - Implement graceful fallback to JSON files if database connection fails or is unreachable.
5. **Testing & Quality Assurance:**
   - Unit tests covering database connection, model relationships, and seed integrity.

## Technical Details

### Database Schema

```text
projects
├── id (string)
├── title (string)
├── description (text)
├── github_url (string, optional)
├── live_url (string, optional)
├── featured (boolean)
├── created_at (datetime)
└── updated_at (datetime)

technologies
├── id (integer)
└── name (string, unique)

project_technologies (association table)
├── project_id (foreign key -> projects.id)
└── technology_id (foreign key -> technologies.id)

now_entries
├── id (integer)
├── category (string)
├── content (text)
└── updated_at (datetime)

reading_items
├── id (integer)
├── title (string)
├── author (string)
├── status (string)
├── rating (integer)
└── notes (text)
```
